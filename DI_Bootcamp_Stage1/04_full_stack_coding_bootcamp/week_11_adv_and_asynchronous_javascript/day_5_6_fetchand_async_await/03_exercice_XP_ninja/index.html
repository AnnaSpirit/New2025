Exercise 2: Analyze #4

This version uses Promise.all() to launch two promises in parallel: one that resolves after 2 seconds and another after 1 second. Both promises start at the same time, but nothing is displayed until both have resolved. Once they are done, their results are printed in the order they appear in the array — not based on which finished first. This ensures synchronized execution, but delays output until everything is complete.

Exercise 3: Analyze #5

In this version, Promise.all() is combined with async/await and immediately-invoked async functions. Both promises are launched at the same time, but their results are displayed as soon as each one finishes, not after both are done. It’s still parallel, but with more responsive output. This approach improves perceived performance and keeps the code easy to read using await syntax.

Exercise 4: Analyze #6

Here, the two promises are launched independently, each with its own .then(). This means they both run in parallel, and their results are printed as soon as they are resolved — like in Exercise 5. However, unlike the previous exercises, there is no error handling or synchronization. If one fails, it won't be caught, and there’s no waiting for both to finish before showing results.
